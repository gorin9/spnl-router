# spnl-router

[matz/spinel](https://github.com/matz/spinel) 向け **ビルド時 controller → 静的 dispatch ジェネレータ**.
Rails の `config/routes.rb` 相当を **AOT 前に Ruby code で吐く**.

[gorin9/spnl-erb](https://github.com/gorin9/spnl-erb) / [gorin9/spnl-schema](https://github.com/gorin9/spnl-schema)
と同じ思想 (build-time codegen, 出力は pure Spinel-friendly Ruby).

## なぜ必要か

Spinel は `send(:dynamic_name)` も `method(:foo)` 配列も扱えないので,
**ルーティングテーブル → 配列 dispatch** は不可能.
すべて **コンパイル時に case/when で展開**する必要がある.

しかし手書きの巨大な case 分岐は管理が辛い → controller 内に **`ROUTES` ハッシュ**で宣言し,
ビルドツールが case/when に展開する.

```
app/blog_controller.rb         spnl-router        app/router.generated.rb        spinel compile
class BlogController     ────────────────────►   module Router                ──────────────────►  native binary
  ROUTES = {                                       def self.dispatch(path)
    "/"    => :index,                                case path
    "/posts/:id" => :show                            when "/" then c.index ...
  }                                                  end
end                                                end
                                                 end
```

## インストール

依存: CRuby (ビルド機にのみ).

```sh
git clone https://github.com/gorin9/spnl-router.git ~/.local/spnl-router
sudo ln -s ~/.local/spnl-router/bin/spnl-router /usr/local/bin/spnl-router
```

または `spinel-packer install gorin9/spnl-router`.

## 使い方

### 入力: 人が書く controller

```ruby
# app/blog_controller.rb
class BlogController
  ROUTES = {
    "/"          => :index,
    "/about"     => :about,
    "/posts/:id" => :show
  }

  def index
    @posts = Post.all
    @page_title = "Latest posts"
    render_posts_index
  end

  def show(id)
    @post = Post.all[id]
    @page_title = @post.title
    render_posts_show
  end

  def about
    @page_title = "About"
    render_about
  end

  # framework helper (Router から呼ばれる)
  def set_chrome(nav, content)
    @active_nav = nav
    @content = content
    @site_name = "spinel.blog"
  end
end
```

### 実行

```sh
$ spnl-router app/blog_controller.rb -o app/router.generated.rb
wrote app/router.generated.rb
```

### 出力

```ruby
# AUTO-GENERATED by spnl-router — DO NOT EDIT
# source: BlogController
module Router
  def self.dispatch(path)
    c = BlogController.new
    body = ""
    nav  = ""
    case path
    when "/"
      body = c.index; nav = "home"
    when "/about"
      body = c.about; nav = "about"
    else
      if path.start_with?("/posts/")
        id = path[7, path.length].to_i
        body = c.show(id); nav = "posts"
      end
      return "404" if body == ""
    end
    c.set_chrome(nav, body)
    c.render_layout
  end
end
```

### 利用側

```ruby
# app.rb
require_relative "blog_controller"
require_relative "router.generated"

# どこか HTTP loop で
html = Router.dispatch(request.path)
respond_v11(fd, "200 OK", "text/html", html, false)
```

## ROUTES 宣言の文法

```ruby
ROUTES = {
  "/static/path" => :action_name,
  "/path/:id"    => :action_with_param,
  "/admin"       => :admin,    nav: "admin"   # 明示 nav (optional)
}
```

- **static path**: そのまま case/when literal に
- **`:id` param**: 1 つ末尾, prefix の長さで substring 取得, `to_i` 変換
- **nav label** (optional): chrome 用. 省略時は path の先頭セグメントから推論
  (`/` → `"home"`, `/about` → `"about"`)

## controller 側の規約

`set_chrome(nav, content)` と `render_layout` を controller に定義する.
spnl-router が生成する dispatcher は必ずこの 2 つを呼ぶ:

```ruby
case path
when ... then body = c.action_name; nav = "x"
...
end
c.set_chrome(nav, body)
c.render_layout
```

`set_chrome` で共通 chrome (site_name, year 等), action method で page-specific data,
`render_layout` で wrap, という分担.

## 制限事項

- **1 controller につき 1 ROUTES**: 複数 controller を束ねたいなら, 親 controller を作って
  `dispatch` を委譲する書き方 (将来サポート検討中)
- **`:id` param は 1 個のみ末尾**: `/users/:uid/posts/:pid` のような nested param は未対応
- **HTTP method は GET 暗黙**: POST/PUT/DELETE を区別したい場合は path の後ろに `#POST` 等を
  付けるか, dispatcher を method 込みで生成する案 (検討中)
- **Regex / glob ルート未対応**: literal prefix の `start_with?` のみ

これらは PoC レベルで止めている. リアルなアプリで必要なら issue で.

## CLI

```sh
spnl-router <controller.rb>                   # stdout
spnl-router <controller.rb> -o FILE           # ファイル出力
spnl-router <controller.rb> --module-name X   # default: Router
```

## ワークフロー統合

### Makefile

```make
app/router.generated.rb: app/blog_controller.rb
	spnl-router $< -o $@

build: app/router.generated.rb
	ruby scripts/erb-compile.rb       # spnl-erb pipeline
	ruby scripts/schema-compile.rb    # spnl-schema pipeline
	spinel app.rb -o bin/app
```

### `.gitignore`

`*.generated.rb` は **コミット推奨** (`db/schema.rb` 流). レビューで dispatch 表が見える.

## ベンチマーク

```
$ time spnl-router examples/blog_controller.rb -o /tmp/router.rb
real    0m0.052s
```

router 自体は 50ms 以下. 大きな controller でも sub-second.

実行時 (Spinel binary) は **case/when の static dispatch**なので
**1 リクエスト数 μs**. Rails の routes (regex マッチ) より桁違いに速い.
